# ROI Classification — Dorsal / Ventral / Non-expressing Assignment

## Overview

This step assigns each matched triplet (promoter–DG2–E6 spot group, from
`../triplet-matching/`) to a spatial expression domain — **Dorsal**,
**Ventral**, or **Non-expressing** — based on which manually-annotated ROI
polygon that nucleus falls inside. Its output feeds directly into
`../shared/plotted-stats/`.

Two scripts, run in this order:

1. **`update_roi_mapping.py`** — updates the embryo → ROI-file
   lookup table after triplet-matching produces corrected data.
2. **`roi_filter_batch.py`** — does the actual point-in-polygon
   classification and produces the final combined output.


---

## 1. `update_roi_mapping.py`

**Purpose:** keep the embryo → ROI mapping table in sync whenever
triplet-matching is re-run (e.g. after the voxel-size fix produced new
triplet coordinates for some embryos), without having to manually re-assign
ROI files that haven't changed.

**What it does:**
1. Reads the corrected triplets CSV from `../triplet-matching/`
   (`ALL_GENES_FINAL_TRIPLETS_FIXED_VOXEL.csv`) and splits it into one CSV
   per embryo.
2. Reads the *existing* mapping table (`ROI_TRIPLET_BATCH.csv`) — a required
   starting input, not generated by any script in this repo (see the main
   `dna-fish/` README for its required columns).
3. For every embryo whose triplets were just corrected: looks up its
   *previously assigned* ROI file from the old mapping (ROI polygons
   themselves haven't changed, only the triplet coordinates), and writes a
   new row pointing to the newly-split triplet file instead.
4. Everything else in the old mapping is carried over unchanged.
5. Writes the result to a **new** file, `ROI_TRIPLET_BATCH_UPDATED.csv` —
   does **not** overwrite `ROI_TRIPLET_BATCH.csv`. Review the printed
   summary, then manually rename/replace once confirmed correct.

**Flags for manual attention:**
- Any embryo with more than one matching row in the old mapping (prints a
  warning, uses the first).
- Any embryo with corrected triplets but **no** row in the old mapping at all
  — these never had an ROI assigned before and need manual `roi_path` entry.


---

## 2. `roi_filter_batch.py`

**Purpose:** the actual classification step — for every embryo, load its ROI
polygons and test which polygon (if any) each triplet's three spots all fall
inside.

**What it does:**
1. Reads `ROI_TRIPLET_BATCH_UPDATED.csv` (the output of step 1 above, once
   confirmed and renamed).
2. For each embryo: loads its triplets CSV and its ROI `.zip` file (Fiji/
   ImageJ ROI set — one polygon per named region, e.g. "Dorsal", "Ventral",
   "Non-expressing").
3. **Classification rule:** a triplet is assigned to an ROI only if **all
   three** of its spots (promoter, E, DG — using pixel coordinates) fall
   inside (or exactly on the boundary of) that polygon. Partial overlap
   doesn't count.
4. **No-ROI case** (e.g. nc14 embryos, which don't have Dorsal/Ventral/NE
   distinctions): triplets are kept unfiltered and labeled `"no_ROI"` rather
   than being dropped.
5. Combines every embryo's classified triplets into one table and writes
   `ALL_GENES_ALL_ROIS_TRIPLETS_WITH_SUMMARY.xlsx` with two sheets:
   - **`Filtered_Triplets`** — every triplet, with `gene_id`, `roi`
     (Dorsal/Ventral/Non-expressing/no_ROI), and `triplet_source` columns
     added.
   - **`Summary_Counts`** — triplet counts per gene × ROI × source file.

This is the final output of the DNA-FISH pipeline — `Filtered_Triplets` is
what `../shared/plotted-stats/updatedwt_new_dataset.py` and
`updatedrnai_new_dataset.py` read directly.

## Required input columns

`ROI_TRIPLET_BATCH.csv` / `ROI_TRIPLET_BATCH_UPDATED.csv` must have at
minimum:

| Column | Description |
|---|---|
| `gene_id` | Gene/condition label for the embryo (e.g. `LacZ`, `Awh`, `SXLGFP`) |
| `triplet_path` | Path to that embryo's `..._TRIPLETS.csv` file |
| `roi_path` | Path to that embryo's ROI `.zip` file (Dorsal/Ventral/Non-expressing polygon annotations) |

Each triplet CSV must have `x_svb_px, y_svb_px, x_E_px, y_E_px, x_DG_px,
y_DG_px` (pixel coordinates — the classification uses pixel space, not
microns).


---

## How to run

```cmd
python update_roi_mapping.py
:: review the printed summary and the new ROI_TRIPLET_BATCH_UPDATED.csv,
:: then manually rename/replace ROI_TRIPLET_BATCH.csv once confirmed

python roi_filter_batch.py
```


---

## Known limitations / open items

- `update_roi_mapping.py` requires a pre-existing
  `ROI_TRIPLET_BATCH.csv` — if this file doesn't exist yet (first-ever run),
  this script can't build it from scratch; it only updates an existing
  mapping.
- Embryos with no prior ROI mapping are printed as warnings but not
  auto-resolved — they need manual `roi_path` entry before
  `roi_filter_batch.py` can classify them.
- The `in_roi()` check requires ALL THREE spots to fall inside the same
  polygon; a triplet spanning a polygon boundary (e.g. one spot just outside)
  is excluded entirely rather than partially counted.
